# Планы

Цель: сделать Chronicle не просто редактором истории, а инструментом, который каждый день следит за репозиторием: за красотой истории, утечками секретов и уязвимыми зависимостями. Проверка зависимостей уже есть. Здесь собраны идеи и то, как их лучше устроить. Готовое описано в [DESIGN.md](DESIGN.md).

## Общий принцип

Любая автоматическая правка проходит тот же путь, что и ручная. Помощник не меняет репозиторий сам, он заполняет черновик:

1. Помощник предлагает правки: новые сообщения, объединения, удаление файла из истории, обновление зависимости.
2. Предложение становится обычным черновиком или обычным коммитом в отдельной ветке.
3. Человек видит результат в истории и в предпросмотре, правит или отклоняет любой пункт.
4. Применение атомарное и отменяется одной кнопкой, как любая правка.

Так новым функциям не нужен свой механизм изменений: движок переписывания, предпросмотр, журнал и отмена уже есть и проверены. Помощник только строит `RewritePlan` или ветку с правками.

## Автоматическая правка истории

**Что:** сделать историю красивой. Понятные заголовки и описания коммитов, объединение «wip» и «fix typo» с коммитом, который они чинят, единый стиль, например Conventional Commits.

**Как:**

- **Без ИИ, сразу.** Простые правила находят очевидное: сообщения `wip`, `fix`, `typo`, `.`, повтор предыдущего заголовка, коммит, который меняет только что добавленные строки соседнего. Для них предлагается объединение с нужным коммитом. Это работает без ключа и без сети.
- **С ИИ, по ключу.** Модели передаётся сообщение коммита, список файлов, статистика и усечённый diff. Она возвращает заголовок, описание и, если нужно, предложение объединить коммиты. Ответ проверяется по строгой схеме и превращается в `CommitEdit` и `TodoItem` черновика.
- **Поставщик на выбор:** Anthropic, OpenAI-совместимый API или локальная модель через Ollama, чтобы код не уходил с компьютера. В ядре один интерфейс `HistoryAssistant`, а поставщики подключаются отдельно.
- **Ключ API** хранится как пароли ключей SSH: только асинхронный `safeStorage`, только в основном процессе, никогда в интерфейсе.
- **Перед отправкой** diff проходит проверку на секреты из раздела ниже. Найденное вырезается, а человек видит, что именно уйдёт на сервер.
- **Настройки стиля:** язык сообщений, длина заголовка, Conventional Commits, правила проекта из файла в репозитории.
- **Объём:** коммиты обрабатываются пачками с ограничением размера, ход показывается в интерфейсе, а работу можно остановить. Предложения появляются в черновике по мере готовности.

## Генерация и улучшение README

**Что:** создать README для проекта без него или улучшить существующий.

**Как:**

- Собрать сведения о проекте: дерево файлов, манифесты зависимостей, скрипты сборки, лицензию, существующий README, последние теги.
- Модель возвращает документ, а приложение показывает его рядом с текущим, как diff. Человек правит текст, и изменение становится обычным коммитом.
- Без ИИ можно предложить каркас по найденным сведениям: название, команды установки и запуска из `package.json`, `Makefile` или `pyproject.toml`.
- Те же поставщики и та же проверка на секреты, что и для истории.

## Проверка чувствительных данных

**Что:** не дать утечь паролям, токенам, ключам и личным данным: ни в новый коммит, ни на сервер, ни в историю.

**Как устроить:**

- **Правила.** Набор шаблонов для известных форматов: токены GitHub, GitLab, AWS, Slack, Stripe, Google, приватные ключи PEM и OpenSSH, строки подключения к базам. Плюс оценка энтропии для неизвестных секретов рядом со словами `password`, `secret`, `token`, `api_key`. Формат правил совместим с gitleaks, чтобы можно было взять их готовый набор и добавить свои.
- **Исключения.** Файл в репозитории, например `.chronicle/secrets-allow`, с отпечатками ложных срабатываний. В нём хранится хеш находки, а не сама строка.
- **Когда проверять:**
  - перед коммитом проверяется индекс; находка показывается в редакторе, и коммит можно отменить или подтвердить;
  - перед push проверяются только уходящие коммиты, это быстро;
  - по кнопке проверяется вся история; каждый уникальный blob читается один раз через `cat-file --batch`, как в очистке истории, поэтому даже большие репозитории проверяются за секунды или минуты;
  - перед отправкой чего-либо модели ИИ.
- **Что предложить:**
  - убрать файл из индекса и добавить его в `.gitignore`;
  - удалить файл из всей истории, это уже умеет движок;
  - **новое:** заменить строку во всей истории на `***REMOVED***`. Для этого движку нужен обработчик содержимого blob, похожий на `TreePruner`: он переписывает изменённые blob и деревья выше них;
  - напомнить, что секрет нужно отозвать, со ссылкой на страницу отзыва у известных сервисов. После push переписывание уже не спасает.
- **Где запускать:** в ядре, в отдельном процессе, чтобы проверка всей истории не тормозила интерфейс. Если установлен gitleaks, его можно использовать как второе мнение.

## Проверка зависимостей: что ещё можно сделать

Сама проверка готова и описана в [DESIGN.md](DESIGN.md#проверка-зависимостей). Идеи, которые остались:

- **Признаки риска,** как в [deprisk](https://github.com/betrayalove/deprisk): заброшенный пакет без выпусков два года, единственный сопровождающий, лицензия вне разрешённого списка.
- **Предсказание исправления по каждому родителю:** ещё до запуска пакетного менеджера сказать, хватит ли обновить lock-файл, какого родителя поднять или исправления нет. Сейчас приложение пробует исправить и проверяет результат.
- **Исправление для других экосистем:** `cargo update -p`, `go get`, `poetry update --lock`, `uv lock --upgrade-package`, `bundle lock --update`, `composer update --no-install`.
- **Связь с историей:** коммит, в котором уязвимая версия попала в lock-файл, и выпуски, теги которых её содержат.
- **Maven и Gradle** через `osv-scanner`, если он установлен: без запуска сборки их зависимости не прочитать.
- **Уведомление** о новой уязвимости при ежедневной проверке, один раз на каждую.

## Остальное

- **Подпись сборок и автоматическая установка обновлений.** Нужны сертификаты Apple и Windows.
- **Помощник доступа для любого remote,** а не только для `origin`.
- **Системный ssh Windows:** маленькая программа askpass вместо скрипта, чтобы окно пароля работало и с ним.
- **Несколько аккаунтов на одном сервере:** выбор ключа для репозитория прямо в интерфейсе.
